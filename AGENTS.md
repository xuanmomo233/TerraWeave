# TerraWeave · 织境工坊

This is a desktop Minecraft map creation workbench for Codex and the user. The user authorizes autonomous changes and control of this workbench and its dedicated test server/world. Reuse `test-server/world`; do not create a server or world copy for each experiment.

- App and MCP: `workbench/tools/creative-workbench.mjs`; persistent Paper bridge: `workbench/server-plugin/WorkbenchLive.java`.
- Start at world scale with `world_map_info`, `planning_state` and `inspect_plan`. Planning polygons, road polylines and markers are not constrained by local voxel window size. Preserve selected geometry, layer, purpose and notes in the discussion context.
- Map terrain comes from the configured Anvil save. Unknown terrain is explicit; never present missing chunks as air or generate them as a side effect of navigation. Refresh only reads the save.
- Use `capture_map` for actual rotated map PNGs and `inspect_captured_plans` for their frozen geometry. Use `browse_world`/`open_plan_detail` for continuous live 3D detail; local windows are transient previews, not project region objects. Read actual coordinate pages before making architectural claims about blocks.
- Use `capture_views` for actual 3D PNGs with six directions, precise world-coordinate cameras, planning overlays and Y cutaways. Distinguish saved map surface, full model renders, live blocks, planning and draft evidence from Minecraft-client screenshots.
- Use `open_world_scene` for panoramic 3D with complete block models and textures. `world_model_tile` supplies actual block states and exposed-face masks; `get_scene_view` reads the user's current free camera. Do not replace visible blocks with colored LOD cubes or require a small local window to see actual materials. Optimize batching, hidden faces and frustum culling instead.
- `capture_world_scene` defaults to the current observed view and freezes its block states, model geometry and texture atlas; `inspect_captured_scene` verifies their hash and revisions. Custom world-coordinate cameras and six angles remain available. Read exact block pages before architectural claims; distinguish workbench lighting/animation from the game client.
- Match capture tools to the current document: use `capture_map` for the 2D map and `capture_views` for design drafts/cutaways. `get_scene_view` includes rendering-resource counts for diagnostics. Captures restore the original camera/document; avoid steering the camera while a capture is in progress.
- Barrier blocks are invisible in scenery, surface maps and solid geometry. `show_invisible` reveals imported red barrier icons as an editor helper; never replace barriers with solid placeholder walls. Preserve their actual world states and collision.
- Camera movement must not recapture or rebuild an already loaded local window. Prepare data on actual editing/navigation requests or explicit refresh. Keep `context_blocks` in snapshot identity; background exclusion uses owning block coordinates, not fragment position, so overhanging grass/leaves are not sliced at window edges.
- The workbench exports draft revisions. World writes are handled by the independent `world_writer` MCP and its plugin. The existing dedicated test world is available to the developer's reversible write acceptance script.
- Prefer `create_draft` with `plan_id` for sparse world-scale designs. Only edited coordinates acquire before-state baselines; arbitrary distant coordinates can belong to one design. Preview with `focus`, inspect, then apply when appropriate. Applied progress is retained so revisions can continue an existing build. World changes enter history; undo/redo preserve later external edits.
- For every AI-built area, select or create its planning object before drafting. Pass that `plan_id` to `create_draft`, and keep later refinements under the same planning object. Split parts into separate planning objects when they should be independently selectable and hideable. After applying the design, verify its committed write receipt and hide/show behavior in the workbench, then restore the previous visibility. Planning visibility preserves the save and edits made outside that construction.
- The same rule covers AI-generated terrain, water, vegetation, plazas and paths written directly into a save. Create the plans before generation and record the owning plan and generated block state with the project. Retain the replaced state for overlays such as paths. Verify the plans one at a time in both panoramic and local 3D views, then restore the user's visibility settings.
- Eye buttons mean hide/show, retaining gray entries in the tree. Planning deletion is separate, undoable and does not remove built world blocks. Do not reintroduce archive terminology or coordinate-box creation as the primary user workflow.
- `project-state/workbench` holds project snapshots, saved regions and captures. Preserve authored data. Generated build files, stale QA artifacts and retired milestone documents are not product data.
- Project region items have stable `entity_id`; `id` pins a retained version. Repeated refreshes and previews reuse content-addressed block data. Old unreferenced working versions are collected; checkpoint meaningful versions. Do not treat the version cache as a list of independent regions.
- The packaged executable is `workbench/bin/TerraWeave.exe`. `native-build` is disposable development cache and may be cleaned after packaging.
- Build in `workbench`: `npm run build`, `npm run build:desktop`. Build the Paper bridge using `tools/build-server.ps1` with PowerShell 7. Unit tests: `npm test`; real map/server/desktop integration: `npm run test:map`; storage regression: `npm run test:storage`; isolated 150% DPI UI verification: `npm run test:ui`. `tools/verify-map-codex.mjs` validates actual independent Codex tool use and image inspection.
- The project-local MCP approval is authorized for this workbench's tools. Do not alter global Codex configuration or unrelated running projects.
