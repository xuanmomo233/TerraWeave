# 织境工坊

Minecraft 地图规划与创作工作台。先在整张世界地图上划分区域、连接道路与标注地点，再与 Codex 讨论并进入三维细化。工作台直接读取已有存档，保存离线草稿，再将固定修订交给配套写入 MCP 与插件。

## 启动与目录

Windows 便携开发包完整解压后，双击第一层的 `织境工坊.exe`。也可运行安装包，选择 English 或简体中文以及安装目录，再从开始菜单启动。两个发行包均内置工作台所用的 Node.js 运行时。

从「文件 → 世界存档来源」选择含 `level.dat` 的 Java 版存档根目录。工作台识别传统主世界区块目录和 26.1 起的 `dimensions/minecraft/overworld/region`，首次进入三维时按存档版本准备 Mojang 原版模型和贴图。资源缓存后可离线使用。

点击标题栏的工程名称，或使用「文件 → 切换工程」。新工程可从空白规划、虚空世界或已有存档开始。选择「新窗口打开」可同时操作多个世界，选择「切换到此工程」会最小化当前窗口。原工程会保留在列表中，每个工程独立保存规划和草稿。

工程列表可重命名工程、打开工程目录及打开关联存档目录。打开已有存档时，只保存原目录的路径，预览直接读取原存档。工程目录保存规划、草稿、快照和缓存，本机创建的虚空世界保存在该工程的 `worlds` 下。

「文件 → 备份当前工程」生成带校验清单的备份文件夹。「恢复工程备份」校验文件后创建独立工程。外部存档随备份保留关联路径，工程内创建的世界随工程文件备份。移动已有存档后，在「世界存档来源」选择新目录并勾选「这是迁移后的同一个存档」。

属性栏中的未保存输入会按对象暂存。正常重启会恢复该工程的三维标签和相机位置。

- `workbench/`：桌面端、Codex 工具、Paper 桥接源码与测试。
- `workbench/project-state/workbench/planning.json`：规划图层、区域多边形、路线、地点和最近 40 步规划撤销。
- `map-view.json`：上次地图中心、比例和旋转角；`map-cache/`：最多 192 个可重建地形图块。
- `workspace.json`：工程及已有局部数据目录。
- `regions/`、`snapshots/`：内部版本描述与按内容去重的方块数据，不直接作为区域列表。
- `drafts/`、`history/`、`captures/`：设计草稿、实际世界修改记录、保存的预览图。
- `test-server/`：Paper 1.20.1 测试服。Java 1.20.1 客户端连接 `127.0.0.1:25573`。

离线读取器识别 [1.20.1 至 26.2 的 22 个 Java 正式版](workbench/minecraft-version.js)的主世界 DataVersion，支持 GZIP、Deflate、无压缩、LZ4 和外置区块。22 个版本均通过 Anvil 离线读取样例。实景验收覆盖现有 1.20.1 地图和 26.2 出图样例。其他发行版的完整实际地图、其他维度和模组存档仍需单独核验。开发工程可通过 `TERRAWEAVE_STATE` 指向独立工程目录。移动程序时保留 `tools` 和 `assets`，并更新本机的 MCP 路径。

## 编辑器操作

顶部为菜单、文档标签和常用操作；左侧为工具栏及规划图层树；中央在地图总览与连续三维场景之间切换；右侧为当前对象属性；底部为编辑历史、预览图片和保留的数据版本。左右及底部面板可拖动调整大小。

选择规划、切换工具和显示／隐藏会立即反馈，再顺序保存；连续点击以最后一次选择为准。规划条目右键提供聚焦、细化、重命名和删除等工作台操作；文本框右键提供剪切、复制、粘贴和全选。界面不使用浏览器的返回、刷新、查看源代码等默认菜单。

窗口使用统一深色顶栏：空白处可拖动，双击切换最大化；右上角提供最小化、最大化／还原和关闭按钮。

1. 打开「地图总览」，查看已有世界地表。「全图」覆盖所有已保存地形；首次打开会优先聚焦有内容的位置。斜线表示未知地形，深色空白表示已生成但没有方块的空域。
2. 用 B 拖框建立区域，O 逐点画多边形，P 画路线，M 放置地点。拖动控制点调整后，按 Enter 或点「保存规划」提交。地图可选择 Y 切片，也可为规划指定最低和最高 Y。规划不受 Minecraft 区块边界、大小或局部预览体积限制。
3. 在右侧填写名称、用途和风格说明；选中对象可整体拖动，或拖动控制点调整边界。左侧分图层管理建筑、道路和地点，支持创建与重命名图层。
4. 眼睛按钮只负责隐藏／显示。隐藏对象仍在树中灰显；「删除规划」或 Delete 移除规划并支持 Ctrl+Z 恢复。删除规划、图层或方案均不会拆除世界中的方块。
5. 点「全景三维」或顶部「三维」，浏览整个已保存世界。实景全部使用方块模型及贴图，保留台阶、树叶、植物、建筑侧面和悬空结构，不按视距替换成纯色体块。模型按批次加载并合并贴图，仅隐藏被不透明方块遮住的面；较大的场景按观察区域和阴影范围驻留真实模型图块，并限制驻留顶点数。双击三维表面进入对应位置的方块编辑，也可从二维地图双击位置或选择规划后「进入三维细化」。局部读取不新增区域条目或世界副本。
6. 创建设计方案，用画笔或 Codex 在任意世界坐标修改稀疏草稿。原始、设计和差异视图帮助核对，再导出明确的修订。「导出方案」生成包含世界 UUID、草稿修订、原始方块和目标方块的 JSON。同一方案的后续修订可以继续交给写入 MCP。

地图右键拖动可任意旋转，角度框支持精确输入，「归北」恢复北向上。三维默认是自由相机：WASD 移动，右键转头，中键平移，空格／E 上升，Q／C 下降，Shift 加速。滚轮向观察方向移动；右侧可调整速度。点击「自由相机」可切换到环绕模式。相机位置与朝向独立于任何固定旋转中心。

右侧相机属性支持输入世界 X／Y／Z、方位角和俯仰角，再点击「应用相机位置与朝向」或 Enter。方位 0° 朝北，90° 朝东；俯仰正值朝上。编辑中的值不会被实时状态回填覆盖。实景默认关闭网格、区域框和规划叠加，编辑辅助可单独开启。

「滚轮灵敏度」默认 20%，独立于 WASD 移动速度；可在右侧调整为 1%–100%，设置会保留。自由相机前后移动、环绕缩放和二维地图缩放都限制单次滚动幅度，避免鼠标或触控板的大幅输入造成视角跳跃。

窗口失焦会停止移动和转头；取消区域拖拽会恢复原边界。关闭最后一个三维文档会返回地图总览。截图时相机暂时锁定，结束后恢复视角；从局部实机视图导出全景图片后，也会回到原来的文档和位置。

移动相机时复用已加载的编辑窗口。较大场景的驻留范围变化时异步准备真实图块，F5 从存档更新模型与光照修订。局部编辑区保存周围方块作为渲染上下文，并按完整方块替换背景，避免水面、草地和跨边界植物留下矩形接缝。

视口右上角的眼睛开关「显示屏障」显示 barrier 的红色图标。实景和地图默认保持屏障透明；局部编辑显示每个屏障的准确位置，全景远处稀疏显示标识，避免密集图标遮住场景。该开关不改变世界方块或碰撞属性。

| 操作 | 控制 |
| --- | --- |
| 地图选择 / 区域 | V 选择与移动；B 拖框；O 多边形 |
| 路线 / 地点 / 平移 | 地图中 P / M / H |
| 选择方块 | 三维中 V，左键点击 |
| 画笔 / 橡皮 | P / E；画笔左键放置相邻方块，Shift 替换当前方块 |
| 视角 | 右键旋转，中键平移，滚轮缩放；Alt+左键也可旋转 |
| 聚焦与方向 | F 聚焦；7 俯视，1 北向，3 东向；G 网格 |
| 漫游 | 开启「漫游」后 WASD，空格上升，C 下降，Shift 加速，右键转向 |
| 保存 | Ctrl+S 保存当前规划或方案属性 |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Y；地图中处理规划，设计文档中处理草稿 |

| 刷新 / 截图 | F5 / Ctrl+Shift+P |

画笔、橡皮和范围填充写入草稿。草稿支持设计、原始、差异视图；绿色新增、橙色替换、红色删除。应用后仍可修订并继续施工。写入 MCP 的提交、撤销和重做会通过插件检查实际方块状态，保留后续外部改动。

选中的规划 ID、精确顶点、道路宽度、图层、备注和版本一起提供给 Codex。相机按钮保存当前所见视角，保留位置、方向与视口比例；Codex 仍可指定六个方向或任意世界相机。全景图片同时保存实际方块状态、模型几何、贴图图集和修订哈希；精细窗口图片另外绑定原始方块快照。后续修改不会覆盖对应讨论上下文，图片面板可浏览和放大实际 PNG。

在「预览图片」中选择一组后点击「删除本组」。需要一起清理多组时，点击「多选」，勾选对应项目，再点「删除所选」。确认删除后，工作台会回收失去引用的方块快照。

## 数据不会因每次刷新而无限增长

地图拖动、旋转、选区只更新轻量规划与单个视图设置文件，不生成全世界快照。地形读取 Anvil 存档，缓存固定名称覆盖并限制数量：二维最多 192 个，完整模型数据 `model-cache/` 最多 192 个。`volume-cache/` 保留场景索引及旧空间分析工具的有限缓存。局部窗口使用 SHA-256 去重的数据对象与有限预览缓存；同一对象反复读取不复制整张地图。只有主动保存图片时才冻结渲染证据。

内存中的模型图块缓存只保留当前世界修订，取消载入会回收尚未提交的图形资源。新场景在完整构建后替换旧场景，防止关闭或切换视图时残留半成品。

默认仅保留当前区域工作版本、最多 3 个临时预览。未引用的旧数据自动回收。草稿基线、手动检查点和已保存图片依赖的数据会保留，以便继续编辑或准确讨论；这些不属于可丢弃缓存。草稿撤销保存稀疏方块差异，最近 20 步，不为每一步复制整张地图。

工具菜单的「整理未引用缓存」立即执行回收。已保存图片和世界修改历史是工程资产，按实际操作保存。

## Codex 接口

`workbench/.codex/config.toml` 配置 `map_workbench`。旧聊天尚未加载工具时，可以在 `workbench` 使用 `node tools/creative-workbench.mjs <工具名> '<JSON参数>'`。

- 总览与导航：`world_map_info`、`world_map_tile`、`world_surface_at`、`open_map`、`browse_world`、`open_plan_detail`。
- 全景三维：`world_scene_info`、`world_model_tile`、`open_world_scene`、`get_scene_view`、`capture_world_scene`、`inspect_captured_scene`。`get_scene_view` 读取用户当前相机；`capture_world_scene` 未指定角度时保存当前视角。全景及精细窗口截图均支持 `show_invisible` 控制屏障图标。`world_volume_tile` 仅作为粗体块空间分析接口，不用于实景画面。
- 规划：`planning_state`、`create_layer`、`update_layer`、`save_plan`、`select_plan`、`inspect_plan`、`delete_plan`、`delete_layer`、`undo_plan`、`redo_plan`。
- 已有局部数据：`list_regions`、`open_region`、`refresh_region`。`entity_id` 是稳定对象 ID，`id` 是具体保留版本；局部窗口大小属于渲染实现，不限制地图规划。
- 精确讨论：`inspect_region`、`read_region_blocks`；有意义的旧版本用 `save_checkpoint` 固定。
- 草稿：`create_draft` 传 `plan_id` 创建地图级稀疏方案；`edit_draft`、`undo_draft`、`redo_draft`、`inspect_draft`、`preview_draft`、`export_draft`、`update_draft`、`delete_draft`。预览可传世界坐标 `focus` 浏览任意施工位置。
- 既有写入记录可通过 `list_history` 查看。后续写入记录由配套写入 MCP 持久化。
- 图片：`capture_map`、`capture_views`、`list_captures`、`read_capture`。`inspect_captured_plans` 读取对应图片冻结的规划几何。返回真实 PNG 内容、世界 UUID、规划／草稿版本、相机与数据哈希。
- 工程：`workspace_status`、`save_workspace`、`list_region_versions`、`compact_storage`。

全景来自已保存的完整区块，使用实际方块状态、模型和贴图。F5 重新读取已经落盘的存档。水面隐藏相邻水方块之间的内部面，共享边界高度，并使用实际水贴图。当前世界中的甘蔗、竹子、炼药锅水面、箱子和旗帜均有渲染路径。

告示牌可以从存档显示两面文字、染色与发光标记。旗帜按存档顺序绘制原版图案，选择容器时可以查看名称、槽位和物品数量。尚未生成的战利品保持待生成状态。实体动画、定制旗帜图案和透明排序仍可能与 Minecraft 不同。未知地形保持未知。预览和规划保存在工程内，实际施工由独立写入链路执行。

## 独立写入链路

`map_workbench` 负责读取存档、规划、预览和导出。需要施工时，`world_writer` 把固定修订交给 Paper 上的 TerraWeave 插件。安装 `TerraWeave.jar` 后，将写入 MCP 的 `TERRAWEAVE_WRITE_BRIDGE` 指向目标服的 `plugins/TerraWeave`。写入端按批次保存请求和回执，失败后可用原操作 ID 续接。[插件安装、MCP 配置和撤销指南](workbench/SDK.md#插件与-mcp-使用指南)

仓库内的开发配置连接已有测试服。部署时使用目标服的插件目录和独立的操作记录目录。

TerraWeave 插件 1.2.0 在 Paper 1.20.1 至 26.2 范围内通过了 19 个官方可用构建的实服验收。箱子、木桶和旗帜均完成写入、撤销、重做及完整 SNBT 比较。1.20.3、1.21.2 和 26.1 在 Paper 官方下载服务中无可下载构建。

新导出的方案携带存档版本。插件在写入前校验目标世界 UUID 和运行版本。撤销和重做会核对方块状态及 NBT，保留之后在目标服做的改动。世界存档和历史记录目前无法跨文件原子提交。[Paper 版本验收明细](workbench/SDK.md#paper-版本兼容)

## 离线光影

在 Windows 工作台的「视图 → 渲染设置」选择光影目录中的原版 ZIP。BSL v8.4 与 Sildur’s Vibrant High v1.51 已在存档场景出图。计算管线使用 OpenGL 4.3，支持 `.csh`、固定或按画面尺寸计算的工作组、二维图像及存储缓冲。可以在光影目录放置同名 `.zip.txt`，按行写入 `选项名=值`，再应用光影。

支持光影包声明的 PNG 纹理。若包声明了模组命名空间的纹理，例如 `fixture_mod:textures/probe.png`，可将导出的 PNG 放在 `shaderpacks/光影包.zip.inputs/assets/fixture_mod/textures/probe.png`。依赖 Distant Horizons 或 Voxy 的实时几何、模组帧缓冲或其他专用输入的包仍需对应数据适配。工作台按包的必需功能报告兼容问题。

## 开发

`npm run build` 构建界面；`npm run build:desktop` 构建并更新 `bin/TerraWeave.exe`，更新前关闭工作台。在 `workbench` 下用 PowerShell 7 执行 `./tools/build-server.ps1` 构建 Paper 插件，输出 `packages/TerraWeave.jar`。`native-build/` 是可回收的开发缓存，运行程序不依赖它。

`npm run test:entities:live` 在已有测试服上验收箱子、木桶和旗帜的写入、撤销、重做与冲突保护。运行前将构建好的新插件放入测试服的 `plugins` 目录，并保持测试服停止。

`npm test` 为单元测试；`npm run test:map` 验证地表、模型及规划核心逻辑；`npm run test:storage` 检查去重与缓存。`npm run test:ui` 在隔离浏览器检查地图绘制、旋转、隐藏／删除／撤销、150% 缩放、面板边界、三维和截图恢复，不改动真实规划。`tools/verify-map-codex.mjs` 用独立 Codex 进程检查工具调用、实际读图及临时规划清理。`npm run test:writer:live` 独立启动已有测试服，执行一次可逆写入并关服。离线界面回归直接读取保存的世界。
